# Architecture

## System Diagram

```
┌─────────────────────────────────────────┐
│       Presentation Layer (Flutter)      │
│  Screens · Cubits/BLoC · Widgets        │
└─────────────────┬───────────────────────┘
                  │ calls use-cases / repositories
┌─────────────────▼───────────────────────┐
│           Domain Layer                  │
│  Use Cases · Repository Interfaces      │
│  Failure Types · Business Rules         │
└─────────────────┬───────────────────────┘
                  │ implemented by
┌─────────────────▼───────────────────────┐
│           Data Layer                    │
│  Repository Impls · Services · Models   │
│  Freezed+JSON serialization             │
└─────────────────┬───────────────────────┘
                  │ reads/writes
┌─────────────────▼───────────────────────┐
│       Firebase / External               │
│  Firestore · FirebaseAuth               │
│  Cloud Functions · Hive (local cache)   │
└─────────────────────────────────────────┘
```

Every feature (`auth`, `student`, `servant`, `team`, `attendance`) is a **vertical slice** with its own `data/`, `domain/`, and `presentation/` folders. Cross-feature concerns live in `lib/core/`.

---

## Layer Responsibilities

### Presentation Layer

- **Screens** — stateless or `StatefulWidget` views; own no business logic.
- **BLoC/Cubit** — translate user events into state objects; call domain use-cases or repository methods directly when no dedicated use-case exists.
- **Widgets** — reusable UI components in `core/widgets/` and per-feature `presentation/widgets/`.

State management uses `flutter_bloc`:
- `AuthBloc` — global singleton managing the entire authentication state machine.
- Feature Cubits (`StudentDataBloc`, `ServletDataCubit`, `TeamCubit`, `AttendanceTakingCubit`, …) — scoped per-screen, provisioned by `AppRouter` or `ChurchApp`.

### Domain Layer

- **Repository interfaces** (`IStudentRepository`, `IAttendanceRepository`, …) — abstractions the presentation layer depends on. Concrete implementations live in `data/`.
- **Use cases** — thin wrappers encoding a single operation: `GetStudentsStreamUseCase`, `CanMutateStudentUseCase`. Encapsulate permission checks and orchestration that would otherwise be repeated in multiple BLoCs.
- **Failure types** — domain exceptions (`AuthFailure`, `AttendanceFailure`, …) that are mapped from low-level SDK errors, keeping Firestore error codes out of the presentation layer.

### Data Layer

- **Repository implementations** — communicate with Firestore via `FirebaseFirestore`. Expose `Stream<T>` for live queries and `Future<T>` for one-shot reads/writes.
- **Services** — fine-grained data collaborators (`FirebaseAuthProvider`, `AuthUserProfileStore`, `StudentQueryService`, `StudentLinkedUserSyncService`). Services are composed into repositories rather than exposed directly to the UI.
- **Models** — `@freezed` classes generated by `freezed` + `json_serializable`. Each model provides `fromMap(Map, docId)` for Firestore document hydration and `toMap()` for writes.

### Core

| Component | Purpose |
|---|---|
| `core/di/injection.dart` | Single `configureDependencies()` function; manual `GetIt` wiring with no annotation-based code-gen |
| `core/routing/app_router.dart` | Imperative `onGenerateRoute` router mapping string routes to guarded screen builders |
| `core/constants/` | `enums.dart` (UserRole, AttendanceStatus, EducationStage, Group), `routes.dart` (string constants), `firestore_collections.dart` (collection names) |
| `core/theme/` | Design tokens: `AppColors`, `AppTypography`, `AppSpacing`, `AppComponentThemes`, assembled in `AppTheme.light()` |
| `core/widgets/` | Shared widgets: form fields, dialogs, snackbars, profile cards, empty states, search panel |
| `core/utils/` | `validators.dart`, `json_converters.dart` (Firestore Timestamp ↔ DateTime), `exception_matchers.dart`, `data_seeder.dart` (dev-only) |

## Design Patterns

### Role-Gated Root Dispatch (`RoleUserRoute`)

`lib/role_user_route.dart` is a `BlocBuilder<AuthBloc>` that renders one of four root widgets based on the current `AuthState`:

```
AuthLoading       → CircularProgressIndicator
AuthAuthenticated → role-switch: AdminDashboard | ServantDashboard | StudentProfile
AuthDegraded      → same as above, with a degraded-mode snackbar
AuthNeedsVerification → VerifyEmailScreen
AuthArchived      → ArchivedAccountScreen
*                 → LoginScreen
```

`AuthDegraded` is a resilience state: when Firestore is unreachable but a cached user exists, the app continues with last-known permissions instead of signing the user out.

### Admin Gate (`AdminGate`)

`AdminGate` (`features/admin/presentation/widget/admin_gate.dart`) wraps every admin-only route in the router. It reads `AuthBloc` state and rejects non-admin users before rendering the `child` widget.

### Reactive Attendance Roster

`AttendanceRepository.watchSessionRosterSnapshot()` combines three Firestore streams using `rxdart.Rx.combineLatest3`:

1. Session document (for open/closed state and student snapshot IDs)
2. Marks subcollection (live attendance marks)
3. Clock stream (polls every 15 s) to re-evaluate effective status without server round-trips

This is the most complex reactive pattern in the codebase and the performance-critical path for the attendance-taking screen.

### Offline Persistence

Firestore is configured with `persistenceEnabled: true` and `cacheSizeBytes: 100MB` in `injection.dart`. This means the UI works offline for read operations, with writes queued and synced automatically.

### Dependency Injection

The entire graph is wired in `configureDependencies()` using `GetIt.registerLazySingleton` (singletons created on first use) and `GetIt.registerFactory` (new instance per call, used for use-cases that are cheap to construct). There are no `@injectable` annotations — the wiring is explicit and auditable at a glance.

## Architectural Decisions

| Decision | Rationale |
|---|---|
| Manual GetIt over injectable codegen | Eliminates a build step and makes the dependency graph readable in one file |
| Freezed models | Immutability prevents accidental mutation bugs; copyWith makes state updates ergonomic |
| `AuthDegraded` state instead of logout on network error | Avoids disruptive UX where a temporary Firestore blip logs out a user mid-session |
| Student roster snapshot stored on session document | Avoids N+1 queries when loading an attendance session; students are resolved at session creation time |
| Firestore security rules replicate domain access rules | Defense-in-depth: rules enforce permissions server-side independent of client logic |
