# Configuration

## Firebase Configuration

### `lib/firebase_options.dart`

Auto-generated by `flutterfire configure`. Contains per-platform `FirebaseOptions` (API key, project ID, app ID, messaging sender ID, storage bucket). **Never commit real credentials to a public repository.**

To regenerate:

```bash
dart pub global activate flutterfire_cli
flutterfire configure --project=<your-firebase-project-id>
```

### `firebase.json`

Firebase CLI project configuration:

```json
{
  "firestore": {
    "rules": "firestore.rules",
    "indexes": "firestore.indexes.json"
  },
  ...
}
```

### `firestore.rules`

Declarative security rules deployed to Firebase. Edit locally, then deploy:

```bash
firebase deploy --only firestore:rules
```

### `firestore.indexes.json`

Composite index definitions. Required for multi-field Firestore queries (e.g., `attendance_sessions` queried by `studentIdsSnapshot` + `teamId`). Deploy:

```bash
firebase deploy --only firestore:indexes
```

## Firestore Settings (Runtime)

Configured programmatically in `lib/core/di/injection.dart`:

```dart
firestore.settings = const Settings(
  persistenceEnabled: true,
  cacheSizeBytes: 100 * 1024 * 1024, // 100 MB
);
```

- **`persistenceEnabled: true`** — enables offline reads and write queuing. The app continues to display data when the device loses network.
- **`cacheSizeBytes: 100MB`** — bounded LRU disk cache, preventing unbounded storage growth.

To disable offline persistence (e.g., for CI/test environments), inject a `FirebaseFirestore` instance with `persistenceEnabled: false`.

## Collection Name Constants

All Firestore collection names are centralised in `lib/core/constants/firestore_collections.dart`:

```dart
class FirestoreCollections {
  static const users               = 'Users';
  static const students            = 'Students';
  static const classes             = 'Classes';           // Teams
  static const attendanceSessions  = 'attendance_sessions';
  static const attendanceMarks     = 'marks';
}
```

> **Note:** The `Classes` collection stores teams. This naming reflects the original domain language and should not be renamed without a Firestore migration.

---

## Named Route Constants

All route strings are defined in `lib/core/constants/routes.dart`. Never use raw strings in `Navigator.pushNamed` calls — always reference these constants.

---

## Enum Values

Enum variants are serialised to/from Firestore as lowercase strings (via `json_serializable` default). Adding a new enum value without a migration plan will cause deserialization failures for documents that don't have the new value.

| Enum | Values |
|---|---|
| `UserRole` | `servant`, `student`, `admin` |
| `AttendanceStatus` | `present`, `absent`, `late` |
| `EducationStage` | `preparatory`, `highSchool`, `college` |
| `Group` | `year1`, `year2`, `year3` |

## Build-Time Code Generation

`freezed`, `json_serializable`, `hive_generator`, and `injectable_generator` require `build_runner`:

```bash
dart run build_runner build --delete-conflicting-outputs
```

Run after modifying any `@freezed`, `@JsonSerializable`, or `@HiveType` annotated class. Generated files (`.freezed.dart`, `.g.dart`) are committed to source control.

---

## Environment Variables

There are no `.env` files or runtime environment variables. Firebase credentials are embedded via `firebase_options.dart`. For CI/CD pipelines, manage secrets using your CI platform's secret store and inject `google-services.json` (Android) / `GoogleService-Info.plist` (iOS) as encrypted artifacts before building.
