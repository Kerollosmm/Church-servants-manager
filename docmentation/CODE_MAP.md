## `lib/` — Application Root

| File | Role |
|---|---|
| `main.dart` | Zone-guarded entry point. Initialises Firebase, calls `configureDependencies()`, installs a global `ErrorWidget.builder` and `FlutterError.onError` handler, then calls `runApp`. Falls back to `_StartupFailureApp` if bootstrap throws. |
| `church_app.dart` | Root `StatelessWidget`. Registers all repositories and shared use-cases as `RepositoryProvider`s, then mounts three global `BlocProvider`s (`AuthBloc`, `StudentProfileCubit`, `ServantDataCubit`). Renders `MaterialApp` with `AppTheme.light()` and `AppRouter.onGenerateRoute`. |
| `role_user_route.dart` | Role-based dispatcher. Listens to `AuthBloc` and renders the correct home screen for each role/state. Contains `_AdminRefreshRequiredScreen` and `_ArchivedAccountScreen` as private inline widgets. |
| `firebase_options.dart` | Auto-generated by `flutterfire configure`. Do not edit manually. |

## `lib/features/`

Every feature follows the same subfolder structure:

```
<feature>/
├── data/
│   ├── models/     # Freezed + JSON-serializable data models
│   ├── repos/      # Concrete repository implementations (Firestore)
│   └── services/   # Fine-grained data services
├── domain/
│   ├── failures/   # Domain-level failure/exception types
│   ├── repos/      # Abstract repository interfaces
│   └── usecases/   # Thin encapsulated operations (when present)
└── presentation/
    ├── bloc/       # BLoC or Cubit classes + state/event files
    ├── screens/    # Full-page widgets
    └── widgets/    # Feature-local reusable widgets
```

### Feature Summary

| Feature | Key Responsibility |
|---|---|
| `auth` | Firebase Auth integration; `AuthBloc` with 9 states; admin provisioning; email verification |
| `student` | Student profile CRUD; linked user sync; filtered queries by team/group |
| `servant` | Servant profile CRUD; `ServantDataCubit` for global servant list |
| `team` | Team CRUD; servant assignment; member management |
| `attendance` | Session lifecycle (create → take → close → reopen); roster snapshot; per-student history and stats |
| `admin` | Admin dashboard; `AdminGate` widget; `AdminPolicy` domain rules |
| `devtools` | Internal diagnostics screen; data seeder; admin-gated |

## `firestore.rules`

Security rules mirror the application's domain rules server-side:

- `Users/{userId}` — users read own doc; admins read any; self-update restricted to `name`, `email`, `isEmailVerified`.
- `Students/{studentId}` — admins: full CRUD; servants: read/write own group/team students; students: read own.
- `Classes/{classId}` — teams collection; admins: full CRUD; servants: read only.
- `Classes/{classId}/attendance_sessions/{sessionId}` — create restricted to active teams + valid payload; update/delete admin only.
- `Classes/{classId}/attendance_sessions/{sessionId}/marks/{studentId}` — create/update when session is open (time-bounded) or reopened by admin; delete also permitted within those windows.
