Observed typing mismatch in generated DI vs usage

Generated config registers AuthService, StudentDataRepository, and ServantDataRepository as interfaces (AuthRepository, IStudentRepository, IServantRepository) while ChurchApp resolves some by concrete type. If no extra registrations exist, GetIt lookups may fail at runtime.

4. API Request Deep-Dive

Trigger -> BLoC/Cubit -> service/repository -> Firebase call -> response model/state.

AUTH Firebase Auth + Users profile

Login / Check Status

  • LoginScreen -> AuthEventSignIn -> AuthBloc._onSignIn
  • AuthService.signIn -> FirebaseAuthProvider.logIn
  • _auth.signInWithEmailAndPassword(email,password)
  • Verified user -> getUserData(uid) -> Users/{uid}.get()
  • Model: AuthUser
  • State: AuthAuthenticated / AuthNeedsVerification / AuthError
  • AuthEventCheckStatus path uses authStateChanges.first, reloadUser(), getCurrentAppUser()

Register / Verify / Reset / Admin Create

  • RegisterScreen -> AuthEventSignUp -> AuthService.signUp -> FirebaseAuthProvider.createUser
  • createUserWithEmailAndPassword + _saveUserToFirestore -> Users/{uid}.set(..., merge:true)
  • AuthEventSendVerification -> sendEmailVerification() -> Firebase user.sendEmailVerification()
  • AuthEventForgotPassword -> sendPasswordResetEmail -> _auth.sendPasswordResetEmail
  • AuthService.createUserAsAdmin -> FirebaseAuthProvider.createUserAsAdmin uses secondary Firebase app/auth, then saves profile to Users
STUDENT Student list, search, CRUD, profile

List / Streams / Search

  • StudentManagementScreen -> StudentsLoadRequested / StudentsSearchRequested / StudentsRefreshRequested / StudentsListeningStopped
  • StudentDataBloc._onLoadStudents -> _subscribeToStudents -> GetStudentsStreamUseCase.call(actor, teamId)
  • Use case chooses watchAllStudents, watchStudentsByClass, watchStudentsByClasses, or watchStudentsByGroup
  • Firestore stream source: Students collection .snapshots()
  • Search path -> StudentDataRepository.searchStudents(query) using name_lowercase range query
  • State: StudentDataLoading -> StudentDataLoaded / StudentDataError

Create / Edit / Delete / Profile

  • StudentEditScreen -> StudentFormSubmitted; StudentDetailScreen -> StudentDeleted
  • StudentDataBloc checks CanMutateStudentUseCase
  • Optional auth account creation via AuthService.createUserAsAdmin
  • Create -> createStudent -> Students/{id}.set
  • Edit -> updateStudent -> Students/{id}.update
  • Role change -> updateStudentAndSyncLinkedUserRole (Firestore batch updates Students + linked Users)
  • Delete -> deleteStudent -> Students/{id}.delete()
  • StudentProfileScreen -> StudentProfileCubit.loadProfile(actor) -> getStudentByUid -> Students.where('uid'...).limit(1).get()
SERVANT Servants stored in Users with role filter

Servant list + search

  • ServantListScreen -> ServantDataCubit.loadServants/searchServants/refreshServants
  • Cubit admin gate: _ensureAdmin(actor)
  • ServantDataRepository.getAllServants / searchServants (cache-first then server in some paths)
  • Firestore query on Users with where('role', isEqualTo: UserRole.servant.name)
  • Search uses name_lowercase range query
  • State: ServantDataLoading -> ServantDataLoaded / ServantDataError

Create / Update / Delete

  • AddEditServantScreen -> createServant / updateServant
  • Optional AuthService.createUserAsAdmin before create
  • createServant -> Users/{docId}.set(data, merge:true)
  • updateServant -> Users/{docId}.update(data)
  • deleteServant does not delete document: it demotes role to student and clears assignment fields in Users/{docId}
TEAM / ADMIN Team CRUD + cross-collection admin mutations

Team CRUD (`Classes`)

  • TeamManagementScreen -> TeamCubit.loadTeamsByGroup/createTeam/updateTeam/deleteTeam
  • TeamRepository.getTeamsByGroup(groupId) -> Classes.where('groupId'...).get(cache/server)
  • getAllTeams / watchAllTeams, watchTeamsByGroup
  • createTeam -> Classes.add(team.toMap())
  • updateTeam -> Classes/{id}.update(team.toMap())
  • deleteTeam -> Classes/{id}.delete()

AdminTeamService transactions / batch

  • assign_servant_dialog.dart -> TeamCubit.assignServant/unassignServant -> AdminTeamService.assignServantToTeam / unassignServantFromTeam
  • Uses Firestore runTransaction to update Classes/{team.id} + servant Users/{servant.docID} assignments
  • TeamMembersScreen -> TeamCubit.setTeamMembers -> AdminTeamService.setStudentsForTeam
  • Uses Firestore batch to update Students, linked Users, and Classes/{team.id}.student_ids
  • _assertAdmin(actor) enforces role check in service
