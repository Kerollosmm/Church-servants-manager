## Fix 1 — Parallelize chunked Firestore reads in `_loadStudentsByIds` and `_loadStudentNamesByIds`

### Files to change
- `lib/Features/admin/data/admin_team_membership_service.dart`  → function `_loadStudentsByIds`
- `lib/Features/attendance/data/repos/attendance_repository.dart` → function `_loadStudentNamesByIds`

### Problem
Both functions iterate over ID chunks with a sequential `for` loop and `await` each chunk
one at a time. For N chunks this is O(N) serial round-trips to Firestore.

### Fix pattern (apply to BOTH functions)
Replace:
```dart
final Map<String, Student> result = {};
for (final chunk in chunks) {
  final snapshot = await _studentsCollection
      .where(FieldPath.documentId, whereIn: chunk)
      .get();
  for (final doc in snapshot.docs) {
    result[doc.id] = Student.fromFirestore(doc);
  }
}
return result;
```
With:
```dart
final snapshots = await Future.wait(
  chunks.map((chunk) => _studentsCollection
      .where(FieldPath.documentId, whereIn: chunk)
      .get()),
);
final Map<String, Student> result = {};
for (final snapshot in snapshots) {
  for (final doc in snapshot.docs) {
    result[doc.id] = Student.fromFirestore(doc);
  }
}
return result;
```
> Note: `_loadStudentNamesByIds` may return `Map<String, String>` (name strings) instead
> of full `Student` objects — adapt the value type accordingly while keeping the same
> parallel pattern.

## Fix 2 — Replace O(N) Firestore real-time listeners in `watchStudentAttendanceHistory`

### File to change
- `lib/Features/attendance/data/repos/attendance_repository.dart` → function `watchStudentAttendanceHistory`

### Problem
The current implementation opens one `snapshots()` Firestore listener **per session**:
```dart
final markStreams = sessions.map(
  (session) => _markDoc(session.teamId, session.id, studentId).snapshots(),
).toList();
return Rx.combineLatestList(markStreams); // N persistent WebSocket connections!
```
For a student with 50+ sessions this holds N open WebSocket connections simultaneously,
consuming both client and server quota.

### Fix
Convert from N real-time listeners to a single one-time batch read per sessions-list
emission. Replace the `snapshots()` fan-out with a `switchMap` that fires `.get()` calls
in parallel whenever the upstream sessions stream emits:

```dart
Stream<List<AttendanceMark?>> watchStudentAttendanceHistory({
  required String studentId,
  required List<AttendanceSession> sessions,
}) {
  if (sessions.isEmpty) return Stream.value([]);

  // One-time parallel reads; re-fires whenever caller re-invokes (e.g. on pagination).
  return Stream.fromFuture(
    Future.wait(
      sessions.map((session) =>
          _markDoc(session.teamId, session.id, studentId)
              .get()
              .then((doc) => doc.exists ? AttendanceMark.fromFirestore(doc) : null)),
    ),
  );
}
```
> If the call-site needs live updates (e.g. reacts to new marks), wrap the outer
> sessions stream in a `switchMap` that calls this as a future, re-fetching when the
> active session changes. Do NOT reopen N listeners.

## Fix 3 — Add WriteBatch chunk guard (>500 limit) in `markAllPresentForRemainingStudents`

### File to change
- `lib/Features/attendance/data/repos/attendance_repository.dart` → function `markAllPresentForRemainingStudents`

### Problem
The current code builds a single `WriteBatch` and adds one `.set()` per unmarked student.
Firestore rejects any batch with more than 500 operations. Although rare for a church app,
it is still a production crash waiting to happen.

### Current code (simplified)
```dart
final batch = _firestore.batch();
int batchCount = 0;
for (final studentId in session.studentIdsSnapshot) {
  if (existingMarkIds.contains(studentId)) continue;
  batch.set(markRef, payload, SetOptions(merge: true));
  batchCount++;
}
if (batchCount > 0) await batch.commit();
```

### Fix
Pre-collect the unmarked IDs, chunk them in groups of 400 (safety margin below 500),
and commit one batch per chunk:

```dart
final unmarkedIds = session.studentIdsSnapshot
    .where((id) => !existingMarkIds.contains(id))
    .toList();

if (unmarkedIds.isEmpty) return;

final chunks = _chunkList(unmarkedIds, 400); // reuse existing helper
for (final chunk in chunks) {
  final batch = _firestore.batch();
  for (final studentId in chunk) {
    final markRef = _markDoc(session.teamId, session.id, studentId);
    batch.set(markRef, _buildMarkPayload(studentId, session), SetOptions(merge: true));
  }
  await batch.commit();
}
```
> Replace `_buildMarkPayload(...)` with whatever map/object the original code builds
> inside the loop. Keep all existing field names identical.

## Fix 4 — Parallelize session mark reads in `getTeamAttendanceStats`

### File to change
- `lib/Features/attendance/data/repos/attendance_repository.dart` → function `getTeamAttendanceStats`

### Problem
The function reads marks for each session sequentially:
```dart
for (final session in sessions) {
  final marksSnapshot = await _marksCol(teamId, session.id).get(); // serial!
  // ... accumulate stats
}
```
For a team with 30 sessions this is 30 serial round-trips.

### Fix
Collect all futures first, await them in parallel, then accumulate stats:

```dart
// Parallel: fire all reads at once
final markSnapshots = await Future.wait(
  sessions.map((session) => _marksCol(teamId, session.id).get()),
);

// Accumulate stats in the same order
for (int i = 0; i < sessions.length; i++) {
  final session = sessions[i];
  final marksSnapshot = markSnapshots[i];
  // ... existing accumulation logic unchanged
}
```

## Bonus Fix B — Harden `admin.test.ts` with a proper Jest mock

### File to change
- `functions/tests/admin.test.ts`

### Problem
The test passes an `adminDb` object that throws on access, relying on the fast-path
never touching it. If `requireAdmin` ever falls through to the slow path the test
will crash with an uninformative error.

### Fix
Use `jest.fn()` to create an explicit mock that records calls:
```typescript
const mockAdminDb = {
  collection: jest.fn().mockReturnThis(),
  doc: jest.fn().mockReturnThis(),
  get: jest.fn().mockResolvedValue({ exists: false, data: () => null }),
};

it('takes fast path when role claim is admin and not archived', async () => {
  const authContext = {
    uid: '123',
    token: { role: 'admin', isArchived: false },
  };
  const result = await requireAdmin(authContext, mockAdminDb as any);
  expect(result).toBe('123');
  expect(mockAdminDb.collection).not.toHaveBeenCalled(); // fast path: DB never touched
});
```

## Bonus Fix C — Align clock periods between `AttendanceHistoryCubit` and `AttendanceRepository`

### Files to change
- `lib/Features/attendance/presentation/bloc/attendance_history/attendance_history_cubit.dart`
- `lib/Features/attendance/data/repos/attendance_repository.dart`

### Problem
`AttendanceHistoryCubit` ticks every **30 seconds** while `AttendanceRepository._watchClock()`
ticks every **15 seconds**. This causes the cubit to emit stale active-session state for
up to 30 seconds when the repository already knows the session closed.

### Fix
Align both to **30 seconds** (or introduce a shared constant):
```dart
// In a shared constants file, e.g. lib/core/constants/timing_constants.dart
class TimingConstants {
  static const activeSessionClockInterval = Duration(seconds: 30);
}
```
Then reference `TimingConstants.activeSessionClockInterval` in both places.
