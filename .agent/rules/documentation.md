# Documentation Standards

## Philosophy
* **Why, not What:** Explain *why* code is written a certain way.
* **User-Centric:** Document for the person using the API.
* **No Redundancy:** Don't restate the obvious (e.g., class name).

## Style
* **Format:** Use `///` for doc comments.
* **Summary:** Start with a concise, single-sentence summary ending with a period.
* **Spacing:** Add a blank line after the summary.
* **Language:** Be brief. Avoid jargon. Use backticks for code.

## Coverage
* **Public APIs:** Mandatory.
* **Private APIs:** Recommended.
* **Libraries:** Add library-level comments for overviews.
* **Details:** Explain parameters, return values, and exceptions.
